# Netty

## NIO 是什么

1. NIO是一种同步非阻塞I/O模型。对应java的.nio包。原理跟redis单线程但是多路复用一样，能处理高并发。
2. NIO提供了Channel Selector Buffer等抽象。

### 对比NIO和Netty

| NIO 概念             | Netty 对应                                 | 作用                  |
| -------------------- | ------------------------------------------ | --------------------- |
| Channel              | Channel                                    | 连接（socket封装）    |
| Selector             | EventLoop（内部封装Selector）              | IO多路复用 + 事件循环 |
| SelectionKey         | Channel + EventLoop 绑定关系               | 事件注册/状态         |
| Buffer（ByteBuffer） | ByteBuf                                    | 数据读写容器          |
| ServerSocketChannel  | ServerChannel（如 NioServerSocketChannel） | 服务端监听            |
| SocketChannel        | NioSocketChannel                           | 客户端连接            |
| 手写事件循环         | EventLoop                                  | 自动事件驱动          |
| 手写处理逻辑         | Pipeline + Handler                         | 责任链处理            |

### channel.writeAndFlush

1. channel.writeAndFlush(msg)的作用是 将消息写入Channel的发送缓冲区并立即刷新到网络中发送出去。
2. channel.write(msg)会进入Pipeline出站然后把数据写入ChannelOutboundBuffer（发送缓冲区）但是不会立即发送；channel.flush()是把缓冲区数据写到socket中发送出去。
3. channel.writeAndFlush(msg)等价于channel.write(msg) + channel.flush()
4. **write是异步的**，成不成功要看结果

   ```java
   import io.netty.channel.Channel;
   import io.netty.channel.ChannelFutureListener;

           channel.writeAndFlush(message).addListener((ChannelFutureListener) future -> {
               if (!future.isSuccess()) {
                   // 写失败意味着指令没有可靠到达 AGV，需要标记失败并推动任务失败。
                   command.setCommandStatus(AgvCommandStatus.FAILED);
                   command.setFinishTime(LocalDateTime.now());
                   persist(command, "Channel write failed", null, null);
                   log.warn("AGV command channel write failed, agvCode={}, taskNo={}, commandId={}, sequenceId={}, channelId={}",
                           command.getAgvCode(), command.getTaskNo(), command.getCommandId(), command.getSequenceId(), channel.id(),  future.cause());
                   transferTaskService.failTask(command.getTaskNo(), "Channel write failed");
               }
           });

   ```

5. channel.writeAndFlush(message) 方法返回结果是ChannelFuture类型，后面的addListener是调用返回结果ChannelFuture的方法。 上面链式调用相当于如下：

   ```java
   ChannelFuture future = channel.writeAndFlush(message);

   future.addListener((ChannelFutureListener) f -> {
       if (!f.isSuccess()) {
           // 写失败处理
       }
   });

   ```

6. 也可以调用ChannelFuture的sync()方法 让 channel.writeAndFlush(message)这个操作变成同步的。==> 但是不建议 没必要。同步的意思就是线程提交channel.writeAndFlush(message)请求后会停止在这里，阻塞等待这次操作完成。异步就是当前线程只负责“提交写请求”提交完之后就往下执行，这次操作完成之后会自己回调listener。

   ```java
   import io.netty.channel.Channel;
   import io.netty.channel.ChannelFutureListener;

           channel.writeAndFlush(message).addListener((ChannelFutureListener) future -> {
               if (!future.isSuccess()) {
                   // 写失败意味着指令没有可靠到达 AGV，需要标记失败并推动任务失败。
                   ......
               }
           }).sync();

   ```

7. 下面的方式 比writeAndFlush x 3 更高效

   ```java
   channel.write(msg1);
   channel.write(msg2);
   channel.write(msg3);
   channel.flush();

   ```

### ctx是什么

1. **ctx是io.netty.channel.ChannelHandlerContext，表示当前Handler在Pipeline中的上下文**。
2. 常用方法：

   ```java
   // 发送数据
   ctx.write(msg);
   ctx.writeAndFlush(msg);

   // 把数据交给下一个Handler
   ctx.fireChannelRead(msg);

   // 获取Channel
   Channel channel = ctx.channel();

   // 获取Pipeline
   ctx.pipeline();
   ```

3. ctx的设计意义:避免每次都走完整 Pipeline,提高性能,更灵活控制数据流。

### ctx.write(msg)和channel.write(msg)的区别

1. 假设Pipeline顺序如下：

   ```java

   Pipeline 顺序:
   Head -> Idle -> FrameDecoder -> ProtocolDecoder -> ProtocolEncoder -> AgvServerHandler -> Tail

   入站 read 方向:
   AGV socket bytes
     -> FrameDecoder
     -> ProtocolDecoder
     -> AgvServerHandler.channelRead0(ctx, AgvMessage)

   出站 write 方向是反着走
   ```

2. ctx.write(msg) 从“当前 handler 的前一个出站节点”开始往 Head 走。channel.write(msg) 从 Tail 开始往 Head 走，等于走完整个出站 pipeline

3. ctx.write(msg)更适合handler内部使用，关注当前处在pipeline的哪个位置；channel.write(msg)更适合handler外部使用，比如service、controller、定时任务等。

### SpringBoot中Netty服务怎么启动？ ==> 实现CommandLineRunner接口，当SpringBoot启动完成，Bean加载完成初始化完成后，自执行CommandLineRunner的run()方法

```java
package com.xb.xsf.module.basic.agv.netty;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.xb.xsf.module.basic.agv.config.AgvProperties;
import com.xb.xsf.module.basic.agv.netty.codec.AgvFrameDecoder;
import com.xb.xsf.module.basic.agv.netty.codec.AgvProtocolDecoder;
import com.xb.xsf.module.basic.agv.netty.codec.AgvProtocolEncoder;
import com.xb.xsf.module.basic.agv.netty.handler.AgvServerHandler;
import io.netty.bootstrap.ServerBootstrap;
import io.netty.channel.Channel;
import io.netty.channel.ChannelInitializer;
import io.netty.channel.ChannelOption;
import io.netty.channel.EventLoopGroup;
import io.netty.channel.nio.NioEventLoopGroup;
import io.netty.channel.socket.SocketChannel;
import io.netty.channel.socket.nio.NioServerSocketChannel;
import io.netty.handler.timeout.IdleStateHandler;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

import javax.annotation.PreDestroy;

@Slf4j
@Component
@RequiredArgsConstructor
public class AgvNettyServer implements CommandLineRunner {

    // AGV 模块配置，来自 application.yml。
    private final AgvProperties properties;
    // JSON 编解码器复用 Spring ObjectMapper。
    private final ObjectMapper objectMapper;
    // 业务 Handler 是 Sharable 的 Spring Bean。
    private final AgvServerHandler agvServerHandler;
    // BossGroup 负责接收 TCP 连接。
    private EventLoopGroup bossGroup;
    // WorkerGroup 负责连接上的 IO 读写。
    private EventLoopGroup workerGroup;
    // 服务端 Channel，用于关闭监听端口。
    private Channel serverChannel;

    @Override
    public void run(String... args) throws Exception {
        // 可按环境关闭 Netty 服务，例如只启动 REST 管理接口。
        if (!properties.getNetty().isEnabled()) {
            log.info("AGV Netty server disabled");
            return;
        }
        // 读取 Netty 配置。
        AgvProperties.Netty netty = properties.getNetty();
        // 多 Reactor 模型：Boss 接连接，Worker 做 IO。
        bossGroup = new NioEventLoopGroup(netty.getBossThreads());
        workerGroup = new NioEventLoopGroup(netty.getWorkerThreads());
        // ServerBootstrap 是 Netty 服务端启动器。
        ServerBootstrap bootstrap = new ServerBootstrap();

        // 配置两个线程组 bossGroup负责接收新线程；workerGroup负责处理已经连接Channel的读写事件
        bootstrap.group(bossGroup, workerGroup)
                .channel(NioServerSocketChannel.class) // 指定服务端使用哪种Channel实现
                .option(ChannelOption.SO_BACKLOG, 128) // 当很多 AGV 或客户端同时连接时，最多允许128个连接在队列里等待 accept
                .childOption(ChannelOption.SO_KEEPALIVE, true) // 给每个客户端连接Channel设置参数，让操作系统在连接长时间空闲时发送TCP keepalive探测包 ==> 跟业务配置的30秒业务心跳判断不一样，这是TCP底层的保活兜底
                .childHandler(new ChannelInitializer<SocketChannel>() {
                    @Override
                    protected void initChannel(SocketChannel ch) {
                        // Pipeline 顺序：心跳检测 -> 拆包 -> 协议解码 -> 协议编码 -> 业务分发。
                        ch.pipeline()
                                .addLast(
                                        new IdleStateHandler(
                                                netty.getReaderIdleSeconds(),
                                                netty.getWriterIdleSeconds(),
                                                netty.getAllIdleSeconds()
                                        )
                                )
                                .addLast(new AgvFrameDecoder())
                                .addLast(new AgvProtocolDecoder(objectMapper))
                                .addLast(new AgvProtocolEncoder(objectMapper))
                                .addLast(agvServerHandler);
                    }
                });
        serverChannel = bootstrap.bind(netty.getPort()).sync().channel();
        log.info("AGV Netty server started, port={}, bossThreads={}, workerThreads={}",
                netty.getPort(), netty.getBossThreads(), netty.getWorkerThreads());
    }

    @PreDestroy
    public void shutdown() {
        log.info("AGV Netty server stopping");
        if (serverChannel != null) {
            // 关闭监听端口。
            serverChannel.close();
        }
        if (bossGroup != null) {
            // 优雅释放 BossGroup 线程。
            bossGroup.shutdownGracefully();
        }
        if (workerGroup != null) {
            // 优雅释放 WorkerGroup 线程。
            workerGroup.shutdownGracefully();
        }
        log.info("AGV Netty server stopped");
    }
}

```

### 怎么判断AGV心跳？是否在线？

1. **Channel的isActive()方法**。

   ```java

   public boolean isOnline(String agvCode) {
     // 获取到channel之后线判断是否active，如果不active则表示TCP连接不可用，不能下发命令
       Channel channel = agvChannelMap.get(agvCode);
       return channel != null && channel.isActive();
   }

   ```

2. **IdleStateHandler** +
   userEventTriggered() 检测心跳是否超时，如果超时就触发READER_IDLE 事件，然后执行userEventTriggered()方法中的内容。

   ```java
   // AgvServerHandler.java
   @Override
   public void userEventTriggered(ChannelHandlerContext ctx, Object evt) throws Exception {
    if (evt instanceof IdleStateEvent && ((IdleStateEvent) evt).state() == IdleState.READER_IDLE) {
        String agvCode = sessionManager.getAgvCode(ctx.channel());
        statusService.markOffline(agvCode, "heartbeat timeout");
        ctx.close(); // 标记对应AGV离线之后 关闭Channel
        return;
    }
    super.userEventTriggered(ctx, evt);
   }

   ```

3. IdleStateHandler是Netty提供的空闲检测处理器，用来检测某个Channel多久没读/写数据了。

   ```
      readerIdleTime多久没有读到数据

      writerIdleTime多久没有写出数据

      allIdleTime多久没有读也没有写
   ```

4. 不同的事件会触发不同的handler中的不同方法。SimpleChannelInboundHandler 是 Netty 提供的入站 Handler 基类。重写SimpleChannelInboundHandler的对应方法

   ```java
   package com.xb.xsf.module.basic.agv.netty.handler;

   import com.xb.xsf.module.basic.agv.config.AgvBusinessExecutorConfig;
   import com.xb.xsf.module.basic.agv.enums.AgvMessageType;
   import com.xb.xsf.module.basic.agv.protocol.AgvMessage;
   import com.xb.xsf.module.basic.agv.service.AgvCommandService;
   import com.xb.xsf.module.basic.agv.service.AgvStatusService;
   import com.xb.xsf.module.basic.agv.session.AgvSessionManager;
   import io.netty.channel.ChannelHandlerContext;
   import io.netty.channel.ChannelHandler;
   import io.netty.channel.SimpleChannelInboundHandler;
   import io.netty.handler.timeout.IdleState;
   import io.netty.handler.timeout.IdleStateEvent;
   import lombok.extern.slf4j.Slf4j;
   import org.springframework.beans.factory.annotation.Qualifier;
   import org.springframework.stereotype.Component;

   import java.util.concurrent.Executor;

   @Slf4j
   @Component
   @ChannelHandler.Sharable
   public class AgvServerHandler extends SimpleChannelInboundHandler<AgvMessage> {

       // 会话管理器负责 agvCode 与 Channel 的双向映射。
       private final AgvSessionManager sessionManager;
       // 状态服务处理注册、心跳、状态上报和离线标记。
       private final AgvStatusService statusService;
       // 指令服务处理 ACK/RESULT。
       private final AgvCommandService commandService;
       // 业务线程池承接数据库和状态机逻辑，避免阻塞 Netty EventLoop。
       private final Executor agvBusinessExecutor;

       public AgvServerHandler(AgvSessionManager sessionManager,
                               AgvStatusService statusService,
                               AgvCommandService commandService,
                               @Qualifier(AgvBusinessExecutorConfig.AGV_BUSINESS_EXECUTOR) Executor agvBusinessExecutor) {
           this.sessionManager = sessionManager;
           this.statusService = statusService;
           this.commandService = commandService;
           this.agvBusinessExecutor = agvBusinessExecutor;
       }

       @Override
       public void channelActive(ChannelHandlerContext ctx) {
           // TCP 建立连接不等于 AGV 上线；必须等 REGISTER 后才认为上线。
           log.info("AGV channel connected, channelId={}, remoteAddress={}", ctx.channel().id(), ctx.channel().remoteAddress());
       }

       @Override
       protected void channelRead0(ChannelHandlerContext ctx, AgvMessage message) {
           // messageType 为空表示协议类型非法，关闭连接避免后续业务误处理。
           if (message.getMessageType() == null) {
               log.warn("AGV message type invalid, agvCode={}, sequenceId={}, channelId={}",
                       message.getAgvCode(), message.getSequenceId(), ctx.channel().id());
               ctx.close();
               return;
           }
           // REGISTER 是唯一允许未注册连接发送的消息。
           if (message.getMessageType() == AgvMessageType.REGISTER) {
               sessionManager.register(message.getAgvCode(), ctx.channel());
           } else if (sessionManager.getAgvCode(ctx.channel()) == null) {
               // 未注册直接上报状态/心跳属于非法流程，关闭连接便于设备侧重连注册。
               log.warn("AGV message before register, agvCode={}, messageType={}, channelId={}",
                       message.getAgvCode(), message.getMessageType(), ctx.channel().id());
               ctx.close();
               return;
           }
           // Handler 只投递事件，不在 EventLoop 中做数据库操作和状态机流转。
           agvBusinessExecutor.execute(() -> dispatch(message));
       }

       @Override
       public void channelInactive(ChannelHandlerContext ctx) {
           // 连接断开后清理 session，并把设备状态标记为离线。
           String agvCode = sessionManager.getAgvCode(ctx.channel());
           sessionManager.remove(ctx.channel());
           statusService.markOffline(agvCode, "channel inactive");
           log.warn("AGV channel inactive, agvCode={}, channelId={}, remoteAddress={}",
                   agvCode, ctx.channel().id(), ctx.channel().remoteAddress());
       }

       @Override
       public void userEventTriggered(ChannelHandlerContext ctx, Object evt) throws Exception {
           // IdleStateHandler 触发读空闲事件，说明超过配置时间未收到心跳或状态报文。
           if (evt instanceof IdleStateEvent && ((IdleStateEvent) evt).state() == IdleState.READER_IDLE) {
               String agvCode = sessionManager.getAgvCode(ctx.channel());
               statusService.markOffline(agvCode, "heartbeat timeout");
               log.warn("AGV heartbeat timeout, agvCode={}, channelId={}, remoteAddress={}",
                       agvCode, ctx.channel().id(), ctx.channel().remoteAddress());
               ctx.close();
               return;
           }
           // 非心跳超时事件交给父类处理。
           super.userEventTriggered(ctx, evt);
       }

       @Override
       public void exceptionCaught(ChannelHandlerContext ctx, Throwable cause) {
           // 协议解析、网络 IO 等异常统一记录并关闭连接，等待 AGV 重连。
           log.warn("AGV channel exception, channelId={}, remoteAddress={}", ctx.channel().id(), ctx.channel().remoteAddress(), cause);
           ctx.close();
       }
   }

   ```

5. 不同的事件会触发什么方法 取决于你写的Handler继承了什么Handler基类。

| 类型     | 常用 Handler 基类                | 常重写方法             | 什么时候触发                    | 常见用途                       |
| -------- | -------------------------------- | ---------------------- | ------------------------------- | ------------------------------ |
| 入站     | `ChannelInboundHandlerAdapter`   | `channelActive()`      | TCP 连接建立                    | 记录连接、初始化会话           |
| 入站     | `ChannelInboundHandlerAdapter`   | `channelRead()`        | 收到入站数据                    | 手动处理消息，需要自己类型转换 |
| 入站     | `SimpleChannelInboundHandler<T>` | `channelRead0()`       | 收到指定类型消息                | 处理解码后的业务对象           |
| 入站     | `ChannelInboundHandlerAdapter`   | `channelInactive()`    | 连接断开                        | 清理 session、标记设备离线     |
| 入站     | `ChannelInboundHandlerAdapter`   | `exceptionCaught()`    | IO/解码/业务异常                | 记录异常、关闭连接             |
| 入站事件 | `ChannelInboundHandlerAdapter`   | `userEventTriggered()` | 用户事件，例如 `IdleStateEvent` | 心跳超时、空闲检测             |
| 入站解码 | `ByteToMessageDecoder`           | `decode()`             | 收到 `ByteBuf` 字节             | 粘包拆包后协议解码             |
| 入站解码 | `LengthFieldBasedFrameDecoder`   | 通常不重写             | 收到 `ByteBuf` 字节             | 按长度字段切完整帧             |
| 出站     | `ChannelOutboundHandlerAdapter`  | `write()`              | 调用 `write/writeAndFlush`      | 出站日志、统一包装、拦截发送   |
| 出站     | `ChannelOutboundHandlerAdapter`  | `close()`              | 调用 `close()`                  | 关闭前处理、资源释放           |
| 出站编码 | `MessageToByteEncoder<T>`        | `encode()`             | 写出指定类型消息                | Java 对象编码成 `ByteBuf`      |

1. 其中SimpleChannelInboundHandler<T>继承了ChannelInboundHandlerAdapter。

#### 心跳检测数据流

1. 正常心跳数据流

   ```

   AGV 客户端
     |
     | 发送 HEARTBEAT 报文
     v
   Netty SocketChannel
     |
     v
   IdleStateHandler
     |
     | 收到读数据，重置 readerIdle 计时器
     v
   AgvFrameDecoder
     |
     | 解决 TCP 粘包/拆包
     v
   AgvProtocolDecoder
     |
     | 校验 magic/version/bodyLength
     | 解析 messageType = HEARTBEAT
     v
   AgvServerHandler.channelRead0()
     |
     | 投递到业务线程池
     v
   agvBusinessExecutor
     |
     v
   AgvServerHandler.dispatch()
     |
     v
   AgvStatusService.handleHeartbeat()
     |
     | 更新 onlineStatus = ONLINE
     | 更新 lastHeartbeatTime = now
     v
   agv_device / statusCache

   ```

2. 如果 30 秒内 AGV 没有发任何数据：

   ```
   AGV 客户端
     |
     | 30 秒没有 HEARTBEAT / STATUS_REPORT / ACK / RESULT
     v
   IdleStateHandler
     |
     | 触发 IdleStateEvent.READER_IDLE
     v
   AgvServerHandler.userEventTriggered()
     |
     | 判断 evt 是 IdleStateEvent
     | 判断 state == READER_IDLE
     v
   sessionManager.getAgvCode(ctx.channel())
     |
     v

     | 更新 runningStatus = OFFLINE

     |

     |
   ```

### 具体的业务操作 如记录AGV状态 任务执行情况等 开线程池让业务线程池解决，不要用Netty的EventLoop 线程

### TCP粘包/拆包怎么解决？

1. TCP传输的是字节流，它只能保证正确的传输顺序，不能保证一次完整的传输所有，有可能多次消息合并在一起连续发送，也可能单词的没有发完整。解决办法：

   (1). 双方约定好固定长度；对应Netty中的FixedLengthFrameDecoder

   (2). 约定用特殊分隔符：如每个消息结尾都用\n换行符；对应Netty中的DelimiterBasedFrameDecoder

   (3). 消息头 + 消息体，在消息头中写明消息体的长度。对应Netty中的LengthFieldBasedFrameDecoder。

```java

package com.xb.xsf.module.basic.agv.netty.codec;

import com.xb.xsf.module.basic.agv.protocol.AgvProtocolConstants;
import io.netty.handler.codec.DelimiterBasedFrameDecoder;
import io.netty.handler.codec.FixedLengthFrameDecoder;
import io.netty.handler.codec.LengthFieldBasedFrameDecoder;

/**
 * 外层 4 字节 totalLength 解决 TCP 粘包/拆包；内层仍保留 magic/version/bodyLength 做协议校验。
 */
public class AgvFrameDecoder extends LengthFieldBasedFrameDecoder {
    public AgvFrameDecoder() {
        super(
                AgvProtocolConstants.MAX_FRAME_LENGTH + 4, // 允许的最大帧长度
                0, // lengthFieldOffset=0 长度字段从第0个字节开始
                4, // lengthFieldLength=4 长度字段占几个字节
                0, // lengthAdjustment 长度值是否需要修正
                4  // initialBytesToStrip=4 解码后丢弃前4个字节
        );
    }
}

整体TCP的帧结构是
第 0 ~ 3 字节：frameLength
第 4 字节开始：真正的 AGV 协议内容

+----------------+-------------------------------+
| frameLength    | AGV protocol body             |
| 4 bytes        | frameLength bytes             |
+----------------+-------------------------------+


```
