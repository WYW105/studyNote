# Flink运行时模型

1. Flink运行时主要由JobManager和TaskManager两种进程构成。
```text
                                Client（提交作业）
                            运行 main() 或 flink run
                              构建并提交 Job
                                  │
                                  │ 提交 Job
                                  ▼
┌───────────────────────────────────────────────────────────────────┐
│                            JobManager                             │
│                      协调、调度、故障恢复                           │
│                                                                   │
│     Dispatcher         ResourceManager          JobMaster         │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘
                                   │
                                   │ 调度 / 状态汇报
                                   ↕
                ┌──────────────────┴───────────────────┐
                │                                      │
                ▼                                      ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│        TaskManager 1         │   │        TaskManager 2         │
│                              │   │                              │

│  │         Slot 1         │  │   │  │         Slot 1         │  │

```

## JobManager：协调者

1. JobManager：负责管理作业运行，不执行具体job逻辑。

2. JobManager包含三个内部组件:   

```text
JobManager
│
├── Dispatcher
│     └── 接收作业提交,启动对应的JobMaster
│
├── ResourceManager
│     └── 管理和分配Task Slot 等计算资源
│
└── JobMaster（每个运行中的 Job 对应一个，负责Job的管控与生命周期）
      │
      ├── Scheduler
      │     └── 任务调度、故障恢复
      │
      └── CheckpointCoordinator
            ├── 触发 Checkpoint
            ├── 收集 Task 的 ACK
            ├── 跟踪 Checkpoint 状态
            └── 管理已完成的 Checkpoint 元数据

```

## TaskManager：真正执行Job中的业务逻辑

1. TaskManager是JobManager之外的独立进程。

2. 一个TaskManager是一个JVM进程，每个TaskManager可以同时运行多个任务。

1. 作业 Job：用户提交给Flink执行的**完整数据处理程序**，由多个算子及其数据流连接关系构成，是Flink调度、生命周期管理与故障恢复的**顶层单元**。
2. 算子 Operator：就是Flink中对数据流执行转换、消费或输出操作的最小功能单元，对应昨天DAG中的一个节点，如Source、Map、Filter、Sink。
3. 子任务 Subtask：算子的一个并行执行实例，一个并行度为N的算子会生成N个Subtask。
4. 任务 Task：Flink调度和执行的基本单位，由一个或多个串联起来的算子对应的Subtask组成。同一个Task内的Subtask们由同一个线程执行。
5. 算子链 Operator Chaining： **Flink的一种运行优化机制**，把多个连续的算子合并到同一个 Task 中，**由同一个执行线程运行**，减少序列化、线程切换与网络开销等。
6. 按键分区 KeyBy: 根据指定Key对数据流进行哈希重分区，使相同Key的记录进入同一个下游算子Subtask。
7. 任务槽 Task Slot： TaskManager提供的资源分配单位。
8. 并行度 Parallelism：一个算子在运行时同时执行的并行实例数量。 
9. 槽共享 Slot Sharing：Flink允许同一个作业中属于兼容Slot Sharing Group的多个Task共享同一个Slot的资源调度机制。但是同一个Job中**同一个算子的多个并行Subtask不能共享Slot，必须分开**！==> 一个Job所需的Slot数量等于Job中算子的最大并行度 ==>    

      Slot数量 = max(各算子的Parallelism)

10. 不同Job的Task不能共享同一个Slot，但是可以运行在同一个TaskManager中（一个TaskManager可以管理多个Slot）。
11. **Task 和 Task 之间线程隔离**。

## Parallelism = 2 和 maxParallelism = 128的区别

1. maxParallelism = 128意味着Keyed State的分配空间划分为128个Key Group。   

并行度为2时：   

| 子任务 | 负责的 Key Group |
| ------ | ---------------- |
| Subtask 0 | 0–63 |
| Subtask 1 | 64–127 |

并行度为4时;   

| 子任务 | 负责的 Key Group |
| ------ | ---------------- |
| Subtask 0 | 0–31 |
| Subtask 1 | 32–63 |
| Subtask 2 | 64–95 |
| Subtask 3 | 96–127 |

2. keyBy(event_id)中的event_id就是key，**对key做哈希映射得到固定的KeyGroup**。**key和KeyGroup的影响是永远不变的**，改并行度也不会变。
3. 当前并行度只决定某个KeyGroup该交给哪一个Subtask来托管。

5. maxParallelism 在首次生成状态快照之后固化；若要保留历史状态，则不可修改；若强行修改，只能舍弃快照、空启动作业 ==> 无法带状态恢复作业了。

# DataStream API 数据流的构建、转换与分区

1. DataStream\<T>是Flink DataStream API中表示一条类型为T的数据流的**逻辑抽象**，**不存放数据**，用来串联算子构建DAG、描述这种数据处理拓扑。

## DataStream类型

1. DataStream有多种类型，其中：   

- DataStream<T>：通用的数据流表示。
- DataStreamSource<T>：Source 创建的流。
- SingleOutputStreamOperator<T>：具有单一主输出类型的转换算子结果，可以设置 name()、uid()、setParallelism() 等。
- KeyedStream<T,K>：按照类型为 K 的 Key 分区、可用于有键状态处理的流，而且可以为每个Key独立地维护状态。
- DataStreamSink<T>：输出算子的配置对象，不是用于继续处理数据的下游流。



4. keyBy是分区路由。根据Key哈希计算Key Group，得到Key Group根据maxParallelism和并行度P确定Subtask。

| event_id | Key Group | 目标 Subtask |
| -------- | --------- | ------------ |
| E100     | 20        | 0            |
| E200     | 110       | 1            |
| E300     | 85        | 1            |
| E100     | 20        | 0            |
| E400     | 45        | 0            |

目标 Subtask 计算公式：   

$$
\text{SubtaskIndex}= \left\lfloor \frac{\text{KeyGroupId}\times P}{\text{maxParallelism}} \right\rfloor
$$

```java

import org.apache.flink.api.common.functions.RichMapFunction;
import org.apache.flink.api.common.typeinfo.Types;
import org.apache.flink.streaming.api.datastream.DataStream;
import org.apache.flink.streaming.api.datastream.KeyedStream;
import org.apache.flink.streaming.api.datastream.SingleOutputStreamOperator;
import org.apache.flink.streaming.api.environment.StreamExecutionEnvironment;
import org.apache.flink.streaming.api.functions.sink.v2.DiscardingSink;

public class DataStreamLesson {

    public static void main(String[] args) throws Exception {

        StreamExecutionEnvironment env =
                StreamExecutionEnvironment.getExecutionEnvironment();

        env.setParallelism(2);

        // 1. 模拟两路输入
        DataStream<String> sourceA =
                env.fromData("E100:10", "E200:20");

        DataStream<String> sourceB =
                env.fromData("E100:30", "E300:BAD");

        // 2. 合并数据流
        DataStream<String> merged = sourceA.union(sourceB);

        // 3. 标准化
        DataStream<String> normalized = merged
                .map(value -> value.trim())
                .returns(Types.STRING)
                .name("Normalize");

        // 4. 过滤无效输入（仅供演示）
        DataStream<String> valid = normalized
                .filter(value -> !value.endsWith(":BAD"))
                .name("Filter Invalid");

        // 5. 按 event_id 分区
        KeyedStream<String, String> keyed = valid
                .keyBy(value ->
                        value.substring(0, value.indexOf(':')));

        // 6. 查看消息进入哪个 Subtask
        SingleOutputStreamOperator<String> routed = keyed
                .map(new RichMapFunction<String, String>() {
                    @Override
                    public String map(String value) {
                        int index = getRuntimeContext()
                                .getIndexOfThisSubtask();

                        return "Subtask=" + index
                                + ", value=" + value;
                    }
                })
                .name("Route Observer")
                .uid("route-observer")
                .setParallelism(2)
                .setMaxParallelism(128);

        // 7. 输出到控制台
        routed.print();

        // 8. 额外挂载一个 Sink（接收后丢弃）
        routed.sinkTo(new DiscardingSink<String>())
                .name("Demo Sink");

        // 9. 执行 Job
        env.execute("DataStream Lesson 2");
    }
}

```

## 有状态算子 Stateful Operator 和 无状态算子Stateless Operator

1. State状态 就是 算子为了处理后续数据，需要跨多条记录保存的信息。
2. 无状态算子：算子的计算只涉及到当前的数据；
3. 有状态算子：算子的计算需要依赖保存的历史数据，如判断某条消息是不是该event_id首条事件，就要记录之前这个event_id有没有过事件。

## Context和Collector

1. context是ProcessFunction的内部类，是上下文，包括时间信息、定时器服务以及向侧输出流发出记录。

```java
package org.apache.flink.streaming.api.functions;

......

public abstract class ProcessFunction<I, O> extends AbstractRichFunction {
    private static final long serialVersionUID = 1L;

    public abstract void processElement(I var1, ProcessFunction<I, O>.Context var2, Collector<O> var3) throws Exception;

    public void onTimer(long timestamp, ProcessFunction<I, O>.OnTimerContext ctx, Collector<O> out) throws Exception {
    }

    public abstract class Context {
        public abstract Long timestamp();

        public abstract TimerService timerService();

        public abstract <X> void output(OutputTag<X> var1, X var2);
    }

    public abstract class OnTimerContext extends ProcessFunction<I, O>.Context {
        public abstract TimeDomain timeDomain();
    }
}


```

2. Collector负责向主输出流发出记录。

```java

......
```

3. 一个算子可以有多个输出流，如两个成功两个失败，其中只有一个是Collector的主输出流，剩下三个都是侧输出流。要使用**OutPutTag**

```java
    private final String id; // 标签名

    private final TypeInformation<T> typeInfo;  //元素类型信息

......
```

```java
public class ValidationFunction
        extends ProcessFunction<String, String> {
        
  private static final OutputTag<String> SUCCESS_B = new OutputTag<String>("success-b") {};
  
  private static final OutputTag<String> FAILURE_A = new OutputTag<String>("failure-a") {};
  
  private static final OutputTag<String> FAILURE_B = new OutputTag<String>("failure-b") {};

  @Override
  public void processElement(
          String value,
          Context ctx,
          Collector<String> out) {
  
      if (value.startsWith("SA:")) {
          out.collect(value);                  // 成功 A：主流
      } else if (value.startsWith("SB:")) {
          ctx.output(SUCCESS_B, value);        // 成功 B：侧流 1
      } else if (value.startsWith("FA:")) {
          ctx.output(FAILURE_A, value);        // 失败 A：侧流 2
      } else if (value.startsWith("FB:")) {
          ctx.output(FAILURE_B, value);        // 失败 B：侧流 3
      }
  }

}

```

## ProcessFunction和KeyedProcessFunction

1. public abstract class KeyedProcessFunction<K, I, O> extends AbstractRichFunction。K是Key类型， I是输入记录类型， O是主输出记录类型。
2. KeyedProcessFunction内部的Context类比ProcessFunction中的Context多了一个getCurrentKey()方法，返回K类型的Key值。
3. KeyedProcessFunction和ProcessFunction都是AbstractRichFunction的子类。

3. 下面类里的open函数 就是UDF生命周期，是上图中的Function.open(OpenContext)。UDF指的就是整个SuccessAdoption类的运行时实例。Function.open(OpenContext)

```java
public final class SuccessAdoption extends KeyedProcessFunction<String, NormalizationResult, byte[]> {
                
    private transient ValueState<NormalizationResult> successBaseline;

    public SuccessAdoption() {
        // 触发者：Java 对象构造阶段
    }
    
    @Override
    public void open(OpenContext openContext) {
        // 触发者：Flink运行时 ==> 函数所属算子开始处理数据前
        var descriptor = new ValueStateDescriptor<>(
                BASELINE_STATE,
                TypeInformation.of(NormalizationResult.class)
        );

        successBaseline = getRuntimeContext().getState(descriptor);
    }

    @Override
    public void processElement(
            NormalizationResult value,
            Context ctx,
            Collector<byte[]> out) {
        // 触发者：Flink运行时 ==> 每条记录到达时 ==> 会执行很多次
    }

    @Override
    public void close() {
        // 触发者：Flink运行时 ==> 函数正常关闭时
    }
}
```
Function.open(OpenContext) 不是在 SuccessAdoption 对象创建时立即执行，而是在Flink完成该函数所属算子的运行时初始化后、开始处理数据前执行。所以Function.open(OpenContext) 是 SuccessAdoption 用户函数实例的运行时初始化回调，而不是 Java 构造方法或对象创建回调。**如果open方法是写在SuccessAdoption类的构造方法里，open方法内部就无法使用Flink RuntimeContext了，因为Flink在setup()阶段才会注入运行时上下文并准备相关基础设施，open() 在这之后初始化用户函数自身需要的运行时资源**。

# Flink State 

## KeyedState 和 OperatorState

1. KeyedState是按Key隔离，必须keyBy之后再KeyedStream中才能用上。定位一条Keyed state的完整主键：   

$$
\mathbf{Operator + StateName + (KeyGroup + Key)}
$$


2. **OperatorState绑定到算子的某个并行实例**。Operator State定位:   

$$
\mathbf{Operator + StateName + Subtask(分配切片)}
$$

3. KeyedState类型：   

| API                  | 每个 Key 保存什么                                   | 典型用途                                         |
| -------------------- | -------------------------------------------------- | ------------------------------------------------ |
| ValueState<T>        | 一个 T 类型的值                                    | 首次成功基线、最新电压、累计数量                 |
| ListState<T>         | 一组 T 类型的元素                                  | 设备最近若干次上报                               |
| MapState<K,V>        | 一个 Key 对应的映射表                              | 一台设备不同故障码的计数                         |
| ReducingState<T>     | 按 ReduceFunction 合并得到的值                     | 增量求和、求极值等                               |
| AggregatingState<IN,OUT> | 按聚合函数维护累加器并产生结果                | 平均值、复杂增量聚合                             |


```text
Flink Managed State
│
├── Keyed State（按键状态）
│   ├── ValueState
│   ├── ListState
│   ├── MapState
│   ├── ReducingState
│   └── AggregatingState
│
└── Operator State（算子状态）
    ├── List State
    │   └── Even-split Redistribution（均匀分配）
    │
    ├── Union List State
    │   └── Union Redistribution（全集分配）
    │
    └── Broadcast State
        └── 广播状态（各并行实例持有相同规则）
```

4. OperatorState中的ListState和KeyedState中的ListState是不同的，不是一个。

4. KeyedState使用的时候clear方法只是清理当前key对应的值，不是把这个state删掉。

```java
/**
 * KeyedState：必须在 keyBy 之后
 * 状态句柄：open() 中获取；processElement 只做读写

public class AllKeyedStateFunc extends KeyedProcessFunction<String, Long, String> {

    private transient ListState<Long> listState;
    private transient MapState<Integer, Long> mapState;

                new ValueStateDescriptor<>("vs_count", Long.class);

        ListStateDescriptor<Long> listDesc =
                new ListStateDescriptor<>("ls_history", Long.class);
        listState = getRuntimeContext().getListState(listDesc);

        // MapState：KV
        MapStateDescriptor<Integer, Long> mapDesc =
                new MapStateDescriptor<>("ms_tag_cnt", Integer.class, Long.class);
        mapState = getRuntimeContext().getMapState(mapDesc);

        // ReducingState：增量归约
        ReducingStateDescriptor<Long> reduceDesc = new ReducingStateDescriptor<>(
                "rs_sum",
                Long::sum,
                Long.class
        );
        reducingState = getRuntimeContext().getReducingState(reduceDesc);

        // AggregatingState：自定义累加器，示例：求平均值
        AggregatingStateDescriptor<Long, long[], Double> aggDesc =
                new AggregatingStateDescriptor<>(
                        "as_avg",
                        new AggregateFunction<Long, long[], Double>() {
                            @Override
                            public long[] createAccumulator() {
                                return new long[]{0, 0}; // sum, count
                            }

                            @Override
                            public long[] add(Long value, long[] acc) {
                                acc[0] += value;
                                acc[1]++;
                                return acc;
                            }

                            @Override
                            public Double getResult(long[] acc) {
                                return acc[1] == 0 ? 0.0 : (double) acc[0] / acc[1];
                            }

                            @Override
                            public long[] merge(long[] a, long[] b) {
                                a[0] += b[0];
                                a[1] += b[1];
                                return a;
                            }
                        },
                        Types.PRIMITIVE_ARRAY(Types.LONG)
                );
        aggregatingState = getRuntimeContext().getAggregatingState(aggDesc);
    }

    @Override
    public void processElement(Long value, Context ctx, Collector<String> out) throws Exception {
        // ValueState 读写
        Long v = valueState.value();
        if (v == null) v = 0L;
        v += value;
        valueState.update(v);
        // valueState.clear();

        // ListState 读写
        listState.add(value);
        // listState.addAll(Collections.singletonList(value));
        // Iterable<Long> iter = listState.get();
        // listState.clear();

        // MapState 读写
        mapState.put(1, value);
        Long mVal = mapState.get(1);
        boolean contain = mapState.contains(1);
        // mapState.remove(1);
        // mapState.entries();

        // ReducingState
        reducingState.add(value);
        Long reduceResult = reducingState.get();
        // reducingState.clear();

        // AggregatingState
        aggregatingState.add(value);
        Double avg = aggregatingState.get();
        // aggregatingState.clear();

        out.collect("key = " + ctx.getCurrentKey()
                + " sum=" + reduceResult
                + " avg=" + avg);
    }
}
```

```java
import org.apache.flink.api.common.state.CheckpointedFunction;
import org.apache.flink.api.common.state.FunctionInitializationContext;
import org.apache.flink.api.common.state.FunctionSnapshotContext;
import org.apache.flink.api.common.state.ListState;

import org.apache.flink.configuration.Configuration;

/**
 * Operator State
 * 两类：getListState / getUnionListState
 * 获取句柄：initializeState
 * 快照：snapshotState
 * 业务读写：map / processElement
 */
public class AllOperatorStateFunc
        extends RichMapFunction<Long, String>
        implements CheckpointedFunction {

    private transient ListState<Long> normalListState;
    private transient ListState<Long> unionListState;

    private Long offset = 0L;

    @Override
    public void open(Configuration parameters) throws Exception {
        super.open(parameters);
    }

    @Override
    public void initializeState(FunctionInitializationContext context) throws Exception {
        ListStateDescriptor<Long> normalDesc =
                new ListStateDescriptor<>("os_normal_list", Long.class);
        normalListState = context.getOperatorStateStore().getListState(normalDesc);

        ListStateDescriptor<Long> unionDesc =
                new ListStateDescriptor<>("os_union_list", Long.class);
        unionListState = context.getOperatorStateStore().getUnionListState(unionDesc);

        // 如果是故障恢复，读取状态
        if (context.isRestored()) {
            for (Long val : normalListState.get()) {
                offset = val;
            }
        }
    }

    @Override
    public void snapshotState(FunctionSnapshotContext context) throws Exception {
        // checkpoint 触发：把最新业务数据刷入状态
        normalListState.clear();
        normalListState.add(offset);

        unionListState.clear();
        unionListState.add(offset);
    }

    @Override
    public String map(Long value) throws Exception {
        offset += value;

        // Operator ListState 读写接口
        normalListState.add(value);
        // normalListState.addAll(Collections.singletonList(value));
        // Iterable<Long> iter = normalListState.get();
        // normalListState.clear();

        unionListState.add(value);

        return "subtask offset: " + offset;
    }
}
```
