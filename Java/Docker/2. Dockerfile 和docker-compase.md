## docker镜像的分层机制

1. 一个Docker镜像的内部是分层的，结构如下：

   ```
   Image
   │
   ├── Layer1
   ├── Layer2
   ├── Layer3
   └── Metadata
   ```

   其中Metadata就是元数据包括启动参数、环境参数ENV等；

2. **dockerfile中写的每一个RUN命令都会生成一个新的镜像层，这些层是只读的不能被删除，因此在写dockerfile文件时要尽量减少RUN命令**
   ==> 生成的镜像才会尽量的小。
3. 镜像层不能被删除，那如果向删除某个缓存:

   ```docker
    RUN apt install xxx

    RUN rm -rf cache
   ```

   上述会产生两个镜像层，RUN apt install xxx制造出Layer2对应软件和缓存；RUN rm
   -rf cache制造出Layer3标记了把Layer2中的缓存删除 ==>
   Layer2不会真的被删除，只是Layer3覆盖在Layer2中做了删除记录不把对应文件显示出来，因此整个镜像文件不会减少！

   ```docker
    RUN apt install xxx && rm -rf cache
   ```

   正确的方式是合并成一个RUN，执行完apt install
   xxx之后删除对应缓存，最终只保留一个没有缓存的Layer。

4. Docker 镜像层（Image
   Layer）默认就是只读（read-only），容器就是在docker镜像上加一个可写层

   ```
   Container
   │
   ├── Writable Layer   ← 可写
   │
   ├── Image Layer4     ← 只读
   ├── Image Layer3     ← 只读
   ├── Image Layer2     ← 只读
   └── Image Layer1     ← 只读
   ```

### docker镜像分层设置的好处

1. 镜像之间可以共享这些层；
2. docker pull的时候更快，某些曾本地已经有了就不用拉取了。
3. 支持多容器共享，同一个镜像如果起多个容器，底层是共享的，容器只需要维护自己的可写层Writable
   Layer。

### Docker Compose和Dockerfile的区别

1. **dockerfile是定义怎么制造一个镜像**；Docker
   Compose定义怎么让多个容器一起跑起来，是**多容器编排**。

   以ragflow项目为例，dockerfile就是写了怎么制造ragflow这个主服务的镜像。docker-compose-base.yml里写了怎么让mysql、redis、ES这些依赖服务运行起来。docker-compose.yml里引入了docker-compose-base.yml让主服务和依赖服务一起运行，即项目启动起来。

```docker
# base stage
# 定义名为 base 的基础阶段，后面的 builder 和 production 都会复用它。
FROM ubuntu:22.04 AS base
# 指定后续命令使用 root 用户执行。
USER root
# 指定 RUN 指令默认通过 /bin/bash -c 执行，而不是系统默认的 /bin/sh -c。
SHELL ["/bin/bash", "-c"]

# 定义构建参数 NEED_MIRROR，默认值为 0；构建时可用 --build-arg NEED_MIRROR=1 覆盖。
ARG NEED_MIRROR=0
# 定义构建参数 LIGHTEN，默认值为 0；用于控制是否构建轻量版镜像。
ARG LIGHTEN=0
# 将构建参数 LIGHTEN 写入镜像环境变量，容器运行时也可以读取。
ENV LIGHTEN=${LIGHTEN}

# 设置镜像内的工作目录；后续 COPY、RUN 等相对路径都会基于 /ragflow。
WORKDIR /ragflow

# Copy models downloaded via download_deps.py
# 创建模型资源目录和用户级 ragflow 缓存目录。
RUN mkdir -p /ragflow/rag/res/deepdoc /root/.ragflow
# 从依赖镜像 infiniflow/ragflow_deps:latest 挂载 /huggingface.co 目录，用来拷贝离线模型资源。
RUN --mount=type=bind,from=infiniflow/ragflow_deps:latest,source=/huggingface.co,target=/huggingface.co \
    cp /huggingface.co/InfiniFlow/huqie/huqie.txt.trie /ragflow/rag/res/ && \
    tar --exclude='.*' -cf - \
        /huggingface.co/InfiniFlow/text_concat_xgb_v1.0 \
        /huggingface.co/InfiniFlow/deepdoc \
        | tar -xf - --strip-components=3 -C /ragflow/rag/res/deepdoc
# 继续从依赖镜像挂载模型目录；当 LIGHTEN 不是 1 时，才拷贝较大的 embedding 模型。
RUN --mount=type=bind,from=infiniflow/ragflow_deps:latest,source=/huggingface.co,target=/huggingface.co \
    if [ "$LIGHTEN" != "1" ]; then \
        (tar -cf - \
            /huggingface.co/BAAI/bge-large-zh-v1.5 \

    fi

RUN --mount=type=bind,from=infiniflow/ragflow_deps:latest,source=/,target=/deps \

    cp /deps/cl100k_base.tiktoken /ragflow/9b5ad71b2ce5302211f9c61530b329a4922fc6a4

# 告诉 python-tika 使用本地 jar 文件，避免运行时联网下载 Tika server。
ENV TIKA_SERVER_JAR="file:///ragflow/tika-server-standard-3.0.0.jar"
# 设置 Debian 包管理为非交互模式，避免 apt install 时等待人工输入。
ENV DEBIAN_FRONTEND=noninteractive

# Setup apt
# Python package and implicit dependencies:
# opencv-python: libglib2.0-0 libglx-mesa0 libgl1
# aspose-slides: pkg-config libicu-dev libgdiplus         libssl1.1_1.1.1f-1ubuntu2_amd64.deb
# python-pptx:   default-jdk                              tika-server-standard-3.0.0.jar
# selenium:      libatk-bridge2.0-0                       chrome-linux64-121-0-6167-85
# Building C extensions: libpython3-dev libgtk-4-1 libnss3 xdg-utils libgbm-dev
# 使用 BuildKit 缓存 apt 下载目录；如果 NEED_MIRROR=1，则先切换到清华 Ubuntu 镜像源，然后安装系统依赖。
RUN --mount=type=cache,id=ragflow_apt,target=/var/cache/apt,sharing=locked \
    if [ "$NEED_MIRROR" == "1" ]; then \
        sed -i 's|http://ports.ubuntu.com|http://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list; \
        sed -i 's|http://archive.ubuntu.com|http://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list; \
    fi; \
    rm -f /etc/apt/apt.conf.d/docker-clean && \
    echo 'Binary::apt::APT::Keep-Downloaded-Packages "true";' > /etc/apt/apt.conf.d/keep-cache && \
    chmod 1777 /tmp && \
    apt update && \
    apt --no-install-recommends install -y ca-certificates && \
    apt update && \
    apt install -y libglib2.0-0 libglx-mesa0 libgl1 && \
    apt install -y pkg-config libicu-dev libgdiplus && \
    apt install -y default-jdk && \
    apt install -y libatk-bridge2.0-0 && \
    apt install -y libpython3-dev libgtk-4-1 libnss3 xdg-utils libgbm-dev && \
    apt install -y libjemalloc-dev && \
    apt install -y python3-pip pipx nginx unzip curl wget git vim less && \
    apt install -y ghostscript

# 如果 NEED_MIRROR=1，则配置 pip 和 uv 使用阿里云 PyPI 镜像；最后通过 pipx 安装 uv。
RUN if [ "$NEED_MIRROR" == "1" ]; then \
        pip3 config set global.index-url https://mirrors.aliyun.com/pypi/simple && \
        pip3 config set global.trusted-host mirrors.aliyun.com; \
        mkdir -p /etc/uv && \
        echo "[[index]]" > /etc/uv/uv.toml && \
        echo 'url = "https://mirrors.aliyun.com/pypi/simple"' >> /etc/uv/uv.toml && \
        echo "default = true" >> /etc/uv/uv.toml; \
    fi; \
    pipx install uv

# PYTHONDONTWRITEBYTECODE=1 禁止 Python 写 .pyc；DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1 简化 .NET 全球化依赖。
ENV PYTHONDONTWRITEBYTECODE=1 DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1
# 把 pipx 安装的命令目录加入 PATH，让 uv 等命令可以直接执行。
ENV PATH=/root/.local/bin:$PATH

# nodejs 12.22 on Ubuntu 22.04 is too old
# 使用 NodeSource 安装 Node.js 20；先移除系统旧版 node/npm/cargo，再安装新版 nodejs。
RUN --mount=type=cache,id=ragflow_apt,target=/var/cache/apt,sharing=locked \
    curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && \
    apt purge -y nodejs npm cargo && \
    apt autoremove -y && \
    apt update && \
    apt install -y nodejs

# A modern version of cargo is needed for the latest version of the Rust compiler.
# 安装 Rust 编译链需要的基础工具；如果 NEED_MIRROR=1，则使用清华 rustup 镜像源。
RUN apt update && apt install -y curl build-essential \
    && if [ "$NEED_MIRROR" == "1" ]; then \
         # Use TUNA mirrors for rustup/rust dist files
         export RUSTUP_DIST_SERVER="https://mirrors.tuna.tsinghua.edu.cn/rustup"; \
         export RUSTUP_UPDATE_ROOT="https://mirrors.tuna.tsinghua.edu.cn/rustup/rustup"; \
         echo "Using TUNA mirrors for Rustup."; \
       fi; \
    # Force curl to use HTTP/1.1
    curl --proto '=https' --tlsv1.2 --http1.1 -sSf https://sh.rustup.rs | bash -s -- -y --profile minimal \
    && echo 'export PATH="/root/.cargo/bin:${PATH}"' >> /root/.bashrc

# 把 Rust 工具链目录加入 PATH，让 cargo、rustc 在后续 Dockerfile 指令中可用。
ENV PATH="/root/.cargo/bin:${PATH}"

# 输出 cargo 和 rustc 版本，用于构建日志确认 Rust 安装成功。
RUN cargo --version && rustc --version

# Add msssql ODBC driver
# macOS ARM64 environment, install msodbcsql18.
# general x86_64 environment, install msodbcsql17.
# 添加微软 apt 源并根据 CPU 架构安装 SQL Server ODBC 驱动。
RUN --mount=type=cache,id=ragflow_apt,target=/var/cache/apt,sharing=locked \
    curl https://packages.microsoft.com/keys/microsoft.asc | apt-key add - && \
    curl https://packages.microsoft.com/config/ubuntu/22.04/prod.list > /etc/apt/sources.list.d/mssql-release.list && \
    apt update && \
    arch="$(uname -m)"; \
    if [ "$arch" = "arm64" ] || [ "$arch" = "aarch64" ]; then \
        # ARM64 (macOS/Apple Silicon or Linux aarch64)
        ACCEPT_EULA=Y apt install -y unixodbc-dev msodbcsql18; \
    else \
        # x86_64 or others
        ACCEPT_EULA=Y apt install -y unixodbc-dev msodbcsql17; \
    fi || \
    { echo "Failed to install ODBC driver"; exit 1; }



# Add dependencies of selenium
# 从依赖镜像挂载 Chrome 压缩包，解压到 /opt/chrome，并创建 chrome 命令软链接。

RUN --mount=type=bind,from=infiniflow/ragflow_deps:latest,source=/chromedriver-linux64-121-0-6167-85,target=/chromedriver-linux64.zip \
    unzip -j /chromedriver-linux64.zip chromedriver-linux64/chromedriver && \

# aspose-slides on linux/arm64 is unavailable
# 根据 CPU 架构安装旧版 libssl1.1 包，解决 aspose-slides 在 Linux 上找不到 libssl 的问题。
RUN --mount=type=bind,from=infiniflow/ragflow_deps:latest,source=/,target=/deps \

USER root

WORKDIR /ragflow

# 先复制 Python 项目元数据和锁文件，利用 Docker 缓存加速依赖安装。
COPY pyproject.toml uv.lock ./

# uv records index url into uv.lock but doesn't failover among multiple indexes
# 使用 uv 根据 uv.lock 创建虚拟环境；轻量版只装基础依赖，完整版安装所有 extras。
RUN --mount=type=cache,id=ragflow_uv,target=/root/.cache/uv,sharing=locked \
    if [ "$NEED_MIRROR" == "1" ]; then \
        sed -i 's|pypi.org|mirrors.aliyun.com/pypi|g' uv.lock; \
    else \
        sed -i 's|mirrors.aliyun.com/pypi|pypi.org|g' uv.lock; \
    fi; \
    if [ "$LIGHTEN" == "1" ]; then \
        uv sync --python 3.10 --frozen; \
    else \
        uv sync --python 3.10 --frozen --all-extras; \
    fi

# 复制前端源码目录到镜像中。
COPY web web
# 复制文档目录到镜像中，前端构建可能会引用它。
COPY docs docs

RUN --mount=type=cache,id=ragflow_npm,target=/root/.npm,sharing=locked \
    cd web && npm install && npm run build

# 复制 .git 目录，用于读取 Git tag/commit 信息生成版本号。
COPY .git /ragflow/.git

# 根据 Git 信息生成 VERSION 文件；LIGHTEN=1 时标记为 slim，否则标记为 full。
RUN version_info=$(git describe --tags --match=v* --first-parent --always); \
    if [ "$LIGHTEN" == "1" ]; then \
        version_info="$version_info slim"; \
    else \
        version_info="$version_info full"; \
    fi; \
    echo "RAGFlow version: $version_info"; \
    echo $version_info > /ragflow/VERSION

# production stage
# 开始 production 阶段，仍然继承 base，但只复制运行时需要的产物，减少最终镜像内容。
FROM base AS production

ENV PYTHONPATH=/ragflow/

# 复制前端源码或相关资源目录到生产镜像。
COPY web web
# 复制 API 服务代码。
COPY api api
# 复制配置目录。
COPY conf conf
# 复制 deepdoc 模块代码。
COPY deepdoc deepdoc
# 复制 rag 核心模块代码。
COPY rag rag
# 复制 agent 模块代码。
COPY agent agent
# 复制 graphrag 模块代码。
COPY graphrag graphrag
# 复制 agentic_reasoning 模块代码。
COPY agentic_reasoning agentic_reasoning
# 复制 Python 项目元数据和锁文件，便于运行时或排查依赖版本。
COPY pyproject.toml uv.lock ./
# 复制 mcp 模块代码。
COPY mcp mcp

COPY plugin plugin

# Copy compiled web pages

COPY --from=builder /ragflow/web/dist /ragflow/web/dist

# 从 builder 阶段复制 VERSION 文件到生产镜像。
COPY --from=builder /ragflow/VERSION /ragflow/VERSION

ENTRYPOINT ["./entrypoint.sh"]
```
